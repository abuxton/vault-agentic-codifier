## 3. What `check.sh` verifies

A layer is any directory under the output root that holds `providers.tf`.

| # | Check |
|---|---|
| 1 | Every `.tf` file starts with `# Generated by vault-brownfield-codifier` and has a `# Capability:` line (CAC7) |
| 2 | Each resource and import type is declared only in a file of its owning capability (conventions section 2.4) |
| 3 | `vault_kv_secret_v2`, `vault_kv_secret`, `vault_generic_secret` and `vault_approle_auth_backend_role_secret_id` are absent |
| 4 | No type and label pair is declared twice in a layer (CAC6) |
| 5 | Every resource has exactly one `import {}` block and every import targets a declared resource; `vault_generic_endpoint` is exempt |
| 6 | No UUID literal outside `imports*.tf`, no `SYNTHETIC-`, no inline `secret_id`, `bindpass`, `client_secret`, `private_key` or `password` literal |
| 7 | `versions.tf` and `providers.tf` exist |

It prints one `VIOLATION:` line per problem, never a value, and exits 1 if there is any. A resource type that
no capability owns is a violation, so a new generator must add its types to `owner()` in `check.sh`.

Ownership of the human auth types: `vault_jwt_auth_backend*` and `vault_ldap_auth_backend*` belong to
`admin-config`; `vault_auth_backend` and `vault_approle_auth_backend*` belong to `auth-mounts`.
